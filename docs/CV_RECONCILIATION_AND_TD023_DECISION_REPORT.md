## 2. CV Reconciliation Findings

All four files were read directly (docx via `extract-text`, PDF via `pdftotext` after confirming a real text layer via `pdffonts`) and their embedded document metadata inspected — not inferred from filenames or content alone.

| File | Metadata evidence | Content |

| `Cloud_Support_Cv.docx` | Creator field blank. Created **11 Sept 2025, 18:13 UTC** — 20 minutes after the PDF. | Same full 6-role history and education/certifications; reworded summary and skills grouping ("Cloud Specialist" framing vs. the PDF's "Cybersecurity Specialist" framing). |
| `Endpoint_Engineer_CV.docx` | Creator: **`python-docx`**, description "generated by python-docx" — a software library signature, not a Word-authored document. Created-date field is a known library placeholder (`2013-12-23`), not a real date. | Only the current role in detail; all prior roles collapsed into one summary line; **no education or certifications section**. |
| `Cloud_Engineer_CV.docx` | Same `python-docx` signature and placeholder date. | Same condensed shape as above; no history before 2022; no education section. |

**Finding:** two files (the PDF and `Cloud_Support_Cv.docx`) are the candidate's real, Word-authored, complete CVs, created 20 minutes apart in the same authoring session. The other two were programmatically generated by a script (the `python-docx` fingerprint), not typed by the candidate, and are role-targeted excerpts missing most of the career history and all education/certification data.

**No files were merged, and no candidate data was invented or altered.** Per the directive, this finding is presented for the project owner's designation, not resolved unilaterally. Recommendation: treat the PDF and `Cloud_Support_Cv.docx` as the primary source pair for Career DNA extraction (reconciling any factual differences between the two explicitly, not silently), and preserve `Endpoint_Engineer_CV.docx`/`Cloud_Engineer_CV.docx` as historical, role-targeted variants — useful later for tailored-application generation, not as primary extraction input now.

## 3. Where this leaves Priority 1

Real CV source material is now available for the first time this project has had it. This directly changes what today's already-built Document Intelligence pipeline can be tested against — up to its current, known limit.

**The limit, unchanged since the last audit:** the pipeline can extract everything from a CV (employment, skills, education), but `document_intelligence_service.apply()` can currently only write the extracted headline back to `Person`. Skills and employment history extracted from a real CV would, today, be discarded rather than written to Career DNA — because neither `skill_service.add_person_skill()` nor `Employment` has any way to record AI-extracted provenance (TD-023, confirmed open in the 8 August audit, reconfirmed unchanged in the MVP-reset audit).

**This is now the single blocking decision** between "the pipeline works" and "your actual employment history is in Career DNA."
